@5.1|Operational readiness
An AI service launches without an on-call owner. What should it add?|Threat-specific triage, containment choices, and evidence requirements|A faster restart command|The model's marketing description|A larger service budget|Different failures require different responses; indiscriminate restarts can destroy evidence or leave the cause intact.
A team has a kill switch but has never exercised it. What is the strongest next step?|Run an authorized controlled test against defined stopping criteria|Assume its presence proves readiness|Test it first during an uncontrolled outage|Add it to the architecture diagram|A response control needs measured operational effectiveness, including whether harmful actions actually stop.
A model rejects too many legitimate requests after an update. What should operations compare?|Observed rejection rates against approved baselines and impact|Average model size|The deployment nickname|The total number of employees|Baselines connect behavioral change to service requirements and help distinguish meaningful degradation from normal variation.
Operations cannot determine who owns the retrieval corpus. What should be assigned?|Ownership for data integrity, updates, and recovery|A generic AI program sponsor|A hardware procurement owner|A social media contact|Supporting data stores need accountable operational owners because their changes affect the deployed system.
A configuration change increases agent autonomy without a model update. What should happen?|Assess and approve the operational change and its risks|Treat it as documentation only|Skip validation because weights are unchanged|Wait for a new vendor model|Authority and configuration changes can materially alter risk independent of model weights.
An incident tabletop uses only ordinary server outages. What AI-specific scenario should be included?|Compromised retrieval content driving unauthorized tool requests|A printer paper outage|A standard password expiration reminder|A scheduled billing renewal|A useful tabletop exercises the distinctive data, model, and agent paths that influence response decisions.
An operations team receives a model but no acceptance criteria. What should handover include?|Expected behavior, limits, monitoring, ownership, and response conditions|The weights' download URL|The parameter count|The developer's preferred prompts|Operational handover must enable teams to recognize unacceptable behavior and take authorized action.

A response playbook requires legal input, but no escalation route exists. An assistant is approved only for drafting but operations enables auto-send. @5.2|Telemetry and evidence
Tool calls are logged without outcomes. What should telemetry add?|Success, denial, failure, and relevant action results|The tool display name|A total call counter|The model greeting|A request record alone cannot show whether a consequential action actually occurred.
Two services use unsynchronized clocks during an incident. What is at risk?|Reliable event ordering and correlation|Model tokenization|Dataset compression|Interface accessibility|Time consistency and known offsets help reconstruct causal sequences across distributed components.
A prompt log includes API keys entered by users. What should monitoring owners do?|Restrict exposure, remediate logging, and assess credential compromise|Copy keys into general analyst dashboards|Assume log access makes reuse authorized|Keep all raw payloads indefinitely|Telemetry can itself expose secrets; protect evidence and handle credentials as potentially compromised.
An alert records an unauthorized retrieval attempt but not the document version. What would improve analysis?|Version-linked retrieval evidence and authorization context|A screenshot of the answer|GPU temperature|The response word count|Document versions and permission context help determine what was available and why access was attempted.
An organization sends every raw completion to a third-party monitoring service. What must be assessed?|Data handling, access, purpose, and retention at that recipient|The monitoring chart style|Whether transport uses HTTPS|The number of dashboard users|Monitoring creates a data-sharing path; encryption in transit does not resolve all handling obligations.
Security logs are stored where the same agent can edit them. What should improve?|Independent integrity-protected logging with restricted write authority|Log verbosity|A larger context window|More frequent agent summaries|An actor should not be able to erase or rewrite the evidence needed to investigate its behavior.
A SIEM sees endpoint alerts but no agent tool events. What should integration add?|Correlated AI action telemetry relevant to detection and response|The model's parameter count|Frontend click colors|Provider marketing feeds|Tool and decision events provide visibility into behavior that conventional endpoint alerts may miss.
A team removes all identifiers from logs and can no longer investigate abuse. What is a better approach?|Minimize content while retaining controlled, necessary correlation identifiers|Log no activity at all|Publish all raw identities broadly|Replace event records with aggregate totals only|Privacy-aware telemetry should balance justified investigative needs with access, retention, and minimization controls.
An AI dashboard measures only response latency. What security visibility is missing?|Access anomalies, policy decisions, data exposure, and action behavior|Average sentence length|The application's theme|The team's model preference|Operational speed is not evidence of secure behavior; monitor events tied to credible threats and controls.
An analyst needs raw prompt evidence for a specific incident. What access pattern is strongest?|Controlled case-specific access with an audit trail|Unrestricted access for every employee|A public export for easier review|Permanent access through a shared credential|Sensitive evidence should be available to authorized investigators without unnecessarily broad or enduring exposure.
A tool call is retried under a new request ID each time. What should tracing preserve?|A parent correlation linking the retry chain|Separate total counts|The latest completion|The first token of each prompt|Retries need causal linkage to distinguish one workflow from unrelated actions and reconstruct effects.
@5.3|Runtime detection

A detection rule flags the word delete, including harmless explanations. What should improve?|Context-aware detection tied to actual attempted actions|A longer keyword list|Lower model temperature|Fewer retained logs|Mentioning an action differs from executing it; focus signals on relevant behavior and consequences.
An assistant sends traffic to an unfamiliar external destination. What should be correlated first?|Identity, tool invocation, data scope, and destination approval|Total daily token spend|Response color coding|The newest dataset size|Outbound anomaly assessment needs to establish who caused it, what was sent, and whether it was authorized.
A compromised document is retrieved by many sessions. Which detection strategy is strongest?|Correlate its version and related suspicious actions across sessions|Review each final answer without shared context|Look only at CPU metrics|Wait for a user complaint|A shared retrieval dependency can create related incidents; cross-session correlation reveals scope and patterns.

A usage spike occurs during an approved load test. What should alert triage use?|Change records, test scope, and actual behavior|The spike's magnitude|The model name|The operator's informal recollection|Context can distinguish authorized testing from abuse, but actual activity still needs to match the approved scope.
A SOC assistant suggests closing alerts containing a phrase supplied by attackers. What is the concern?|Adversarial manipulation of triage decisions|Guaranteed model theft|A storage availability issue|A UI defect|Attacker-controlled content can influence generated triage; validate recommendations against independent evidence and workflow rules.
Repeated queries probe whether a named person was in training. What threat should be considered?|Membership inference attempts|Routine model drift|Ordinary artifact signing|Standard capacity planning|Queries targeting individual training inclusion may indicate a privacy attack rather than normal task usage.
Many near-identical queries map a model's decision boundary. What should monitoring assess?|Potential extraction or adversarial probing in context|Whether each request passes syntax validation|Billing payment status|Keyboard activity|A single valid query may be benign; aggregate patterns can reveal efforts to imitate or attack the model.
An agent's tool usage changes immediately after a memory update. What should investigation compare?|Memory content, update provenance, and the resulting action chain|The current system uptime|Dataset row count|Overall benchmark scores|Persistent attacker-influenced state can affect later behavior; examine the state change and downstream effects.
An AI-assisted threat hunt finds a suspicious pattern. What should establish an incident finding?|Validated supporting telemetry and analyst assessment|The model's confident wording alone|The number of times the model repeats it|A fabricated citation in the answer|Generated hypotheses should guide investigation, not substitute for verified evidence.
@5.4|Vulnerability and posture management
A vulnerability affects a model-loading library used only in training. How should it be prioritized?|By exposure, execution path, privileges, and artifact impact|Ignore it because inference is separate|Use only the package's popularity|Treat all training vulnerabilities as low risk|Training compromise can affect artifacts or credentials; assess the actual path and consequences.
A scanner marks an unused dependency critical. What should validation establish?|Whether the vulnerable component is present, reachable, and consequential|The severity label|The vendor's stock price|The model accuracy score|Prioritization should combine reported severity with actual exposure and business impact.
A legacy model cannot be patched immediately. What should risk treatment consider?|Usage restrictions, isolation, monitoring, and a replacement plan|Permanent unreviewed exception|Removal of all vulnerability tracking|A new model nickname|Compensating controls can reduce exposure temporarily but need accountability and a plan for unsupported risk.
A posture report counts closed tickets but ignores recurring failures. What should be measured?|Effective remediation and recurrence of the underlying issues|Ticket title length|Number of vendors|Monthly token savings|Closure volume does not prove risk reduction; verify fixes and observe whether the same failure returns.
An AI asset inventory excludes inference endpoints created by developers. What should discovery cover?|Actual deployed services and unauthorized or shadow endpoints|Procurement-approved model names|Production billing tags|Centrally documented URLs|Exposure assessment requires visibility into real reachable assets, not only approved records.
A supplier discloses an exploitable issue in a pinned model package. What should the owner do?|Identify affected deployments and apply risk-based remediation|Assume pinning prevents vulnerabilities|Update the documentation link|Wait until the package name changes|Pinning supports reproducibility, not immunity; track disclosures and remediate affected versions.
An AI security review occurs only at initial release. What should be added?|Continuous or periodic reassessment tied to change and exposure|Annual license renewal|A one-time benchmark|A permanent approval certificate|Models, dependencies, data, and threats change after launch; assurance must continue over the lifecycle.
A patch fixes a library flaw but changes tokenization behavior. What should validation include?|Security remediation and regression of relevant application behavior|The scanner's clean result|Installation success|Smaller artifact size|Patching should remove the vulnerability without silently breaking correctness or security assumptions elsewhere.
A vulnerability register lacks business context. What would help decision-makers most?|Affected workflows, reachable assets, impact, owners, and treatments|More technical acronyms|A longer list of generic threats|Vendor rankings|Context connects technical findings to actionable business priorities and accountable remediation.
An endpoint is intended to be private but is internet accessible. Which evidence should drive priority?|Actual reachability, authentication, data, and available actions|Its internal label|The original architecture intention|Whether it appears in search engines|Exposure is determined by deployed behavior; names and intent do not enforce boundaries.
A model's unsafe behavior persists after an unrelated software update. What should the owner avoid assuming?|That a successful patch necessarily remediated the behavioral flaw|That regression tests are relevant|That the model needs an owner|That evidence should be retained|Different issues require targeted verification; changing software does not prove the reported failure is fixed.

What should containment include?|Quarantine the document and restrict affected execution paths|Delete one final answer|Increase the search result count|Dismiss the alert|Contain both the entry point and its action consequences while preserving evidence for scope and cause analysis.
A suspected poisoned model is serving critical requests. What should the team evaluate?|Targeted isolation or trusted rollback with continuity and evidence preservation|Automatically destroy every model artifact|Ignore the issue until retraining finishes|Notify the model vendor|Containment balances ongoing harm, continuity, and investigation; choose authorized actions suited to the actual exposure.

An incident spans a vendor-hosted model and internal tools. A responder restores service before containing the compromised tool.
